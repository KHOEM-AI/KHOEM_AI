# KHOEM_AI · ទិន្នន័យចំណេះដឹងខ្មែរ (Khmer Knowledge Data)

ឯកសារនេះពន្យល់ពីទិន្នន័យ Q&A ភាសាខ្មែរដែល KHOEM_AI ផ្តល់តាម `GET /api/khmer`

### ប្រធានបទក្នុងទិន្នន័យបន្ថែម

- ចំណេះដឹងទូទៅ ជីវិតប្រចាំថ្ងៃ វប្បធម៌ និងប្រពៃណីខ្មែរ
- ការសន្ទនាប្រចាំថ្ងៃ (ការស្វាគមន៍ ការអរគុណ ការសួរសុខទុក្ខ)
- ព័ត៌មានសុខភាពទូទៅ — ផ្តល់តែព័ត៌មានទូទៅ ជំហានបន្ទាប់ និងពេលត្រូវជួបអ្នកជំនាញ **មិនមែនការវិនិច្ឆ័យ ឬវេជ្ជបញ្ជាទេ**
- ជំនួយការសរសេរកូដ (coding) ជាភាសាខ្មែរ
- វិទ្យាសាស្ត្រ (រូបវិទ្យា គីមីវិទ្យា ជីវវិទ្យា តារាសាស្ត្រ ផែនដី គណិតវិទ្យា)
- អេឡិចត្រូនិច និងប្រព័ន្ធអេឡិចត្រូនិចទូទៅ (សមាសធាតុ protocol សេនស័រ សុវត្ថិភាពអគ្គិសនី)
- យោធា និងសន្តិសុខ — ចំណេះដឹងសព្វវចនាធិប្បាយទូទៅប៉ុណ្ណោះ (រចនាសម្ព័ន្ធ ច្បាប់មនុស្សធម៌អន្តរជាតិ សុវត្ថិភាពមីន/UXO) **គ្មានវិធីផលិតអាវុធ**
- ឧស្សាហកម្មខ្នាតធំ និងតូច (រោងចក្រ គុណភាព សុវត្ថិភាពការងារ SME ខ្សែសង្វាក់ផ្គត់ផ្គង់)
- ម្ហូបខ្មែរ (ចម្លើយខ្លីៗ)

## ២. ទម្រង់ entry

```ts
// [ "trigger1|trigger2|trigger3", "ចម្លើយ" ]
export const L1_032: [string, string][] = [
  ["ឈ្មោះ|ឈ្មោះបំប្លែង","ចម្លើយជាអក្សរធម្មតា"],
];
```

- ចម្លើយជា `string` ធម្មតាតែប៉ុណ្ណោះ។
- ចម្លើយដែលត្រូវគណនា (កាលបរិច្ឆេទ ម៉ោង អនុគមន៍) **មិនដាក់ទីនេះទេ** ពួកវានៅក្នុងកម្មវិធី AI។

## ៣. របៀបស្វែងរក (`src/khmer/search.ts`)

1. អាន `KHMER_ALL_ENTRIES` តាមលំដាប់ ថ្នាក់ 1 → 2 → 3 ហើយ part តាមលេខ។ ពេល trigger ស្ទួន **entry ដែលនៅមុនឈ្នះ** (first-wins) ដូច្នេះចម្លើយចាស់មិនត្រូវបានប្តូរដោយទិន្នន័យថ្មីទេ។
2. `normKhmer()` (`src/khmer/norm.ts`) កែ trigger និងសំណួរ៖ NFC, ដកតួអក្សរទទេ zero-width (U+200B–200D, FEFF), `trim`, តូចអក្សរ, ដកសញ្ញាចុងឃ្លា `? ។ ! ！ ？ , ， . ៖ ; ； :`, បង្រួមដកឃ្លាច្រើនទៅមួយ។
3. `GET /api/khmer?q=...&exact=1` — ស្វែងរកត្រូវ 100% តែប៉ុណ្ណោះ មិនទាយ។
4. `GET /api/khmer?q=...` — ស្វែងរកត្រូវ 100% មុន បើអត់ទើបប្រើ edit-distance តូច (fuzzy) ហើយបើមានចម្លើយស្មើគ្នាច្រើនខុសគ្នា វាឆ្លើយ `null`។
5. សំណួរខ្លីពេក (ឧ. `abc`) ឬមិនស្គាល់ ឆ្លើយ `found: false`។

> ចំណាំ៖ បើរកមិនឃើញត្រូវ 100% ទើបប្រើ `foldKhmer()` ជាជំនួយ (ប្តូរ `ឲ`→`ឱ` និង `្ដ`→`្ត`)។ បើ trigger ពីរដែលខុសតែអក្ខរាវិរុទ្ធនេះមានចម្លើយខុសគ្នា វាមិនទាយទេ (ឆ្លើយ `null`)។ កម្មវិធី AI ប្រើ `fold` ផ្ទាល់ខ្លួន ដូច្នេះពេលដកស្ទួនទិន្នន័យពីរកន្លែង ត្រូវពិចារណាភាពខុសគ្នានេះ។

## ៤. ការប្រើប្រាស់ពីកម្មវិធី AI

- `AI/src/ai/khoem.mjs` សួរ API `8790` ជាមុនគេ (`KHOEM_AI khmer`) ហើយបើអត់ឃើញចម្លើយ ទើបធ្លាក់ទៅ `khmer.mjs` ក្នុង `AI` ជា fallback។
- ដូច្នេះកែ **នៅទីនេះ** (KHOEM_AI) ជាប្រភពតែមួយ។ កុំថែមទិន្នន័យស្ទួនក្នុង `AI` លុះត្រាតែចេតនា។

## ៥. របៀបបន្ថែមទិន្នន័យដោយសុវត្ថិភាព

ច្បាប់សំខាន់៖ **កុំកែ part ដោយដៃ** ប្រើ tool ដែលបង្កើត `index.ts`, `README.md` និង `ORIGIN.tsv` ឱ្យស្មើគ្នាជានិច្ច។

1. រៀបចំ entries ថ្មីក្នុងឯកសារអត្ថបទ (មួយបន្ទាត់ម្តង) ជាទម្រង់ `trigger|alias :: ចម្លើយ` ឬ `["trigger|alias","ចម្លើយ"],`។
2. ពិនិត្យមុន (មិនសរសេរអ្វីទេ)៖ ឧបករណ៍ដកស្ទួន (trigger ណាដែល `normKhmer(trigger)` មានរួច ឬស្ទួនក្នុងឯកសារ) ពិនិត្យប្រវែងចម្លើយ និងពាក្យមិនស្គាល់៖

```bash
cd ~/KHOEM_AI/KHOEM_AI/localization
node tools/check-new-entries.mjs ~/new.txt
```

3. សរសេរ entries ថ្មីតែប៉ុណ្ណោះ ទៅ **ចុងបញ្ចប់នៃថ្នាក់ 1** (part ចុងក្រោយ; ពេញ 1,000 entries ឬ 400,000 bytes ចាប់ផ្តើម part ថ្មី) ហើយ regenerate `index.ts`, `README.md`, `ORIGIN.tsv` (origin ជា `hand-typed`)៖

```bash
node tools/check-new-entries.mjs ~/new.txt --write
```

4. ប្តូរចម្លើយ entry ដែលមានរួច (key ត្រូវតែដូចគ្នាបេះបិទ; entry នៅ part/ថ្នាក់ដដែល)៖
   `node tools/replace-answers.mjs fixes.txt` (សាកល្បង) រួច `--write`។
5. ផ្ទៀងផ្ទាត់៖

```bash
rm -rf dist && npm run build     # ឬ npm run verify; build មិនលុប dist ចាស់ទេ ដូច្នេះលុបមុនម្តង
npm run verify          # build + duplicate check + locale validation + tests
git diff --check
```

6. Commit តាមឈ្មោះឯកសារ (`git add <file>`) មិនប្រើ `git add .`។
7. បន្ទាប់ពី `npm run build` ត្រូវបិទបើក `ai` ឡើងវិញ ទើប API `8790` ប្រើ `dist` ថ្មី។

tools ផ្សេងទៀត (ទាំងអស់អានពី `src/khmer/levels` ផ្ទាល់ មិនត្រូវការ build): `export-khmer.mjs` (បញ្ចូលគ្នាជាឯកសារតែមួយ), `compare-answers.mjs` និង `missing-from-repo.mjs` (ប្រៀបធៀបឯកសារធំលើទូរសព្ទ), `verify-levels.mjs <git-ref>` (បង្ហាញថា entries ដូចកំណែចាស់), `khmer-words/extract.mjs`។ tools ចាស់សម្រាប់ទម្រង់ `data*.ts` នៅ `tools/legacy/` (រក្សាទុកតែប្រវត្តិ កុំរត់)។

## ៦. ដែនកំណត់ដែលត្រូវដឹង

- ខ្លឹមសារភាគច្រើន **សរសេរដោយ AI ហើយមិនទាន់ត្រូវបានមនុស្សពិនិត្យទាំងអស់ទេ** ជាពិសេសពាក្យបច្ចេកទេសខ្មែរ (វិទ្យាសាស្ត្រ អេឡិចត្រូនិច ឧស្សាហកម្ម) និងចម្លើយសុខភាព។ ត្រូវការអ្នកជំនាញខ្មែរពិនិត្យមុនប្រើជាផ្លូវការ។
- ព័ត៌មានដែលផ្លាស់ប្តូរតាមពេល (តម្លៃ ច្បាប់ ឋានៈ) ត្រូវផ្ទៀងផ្ទាត់ជាមួយប្រភពថ្មីៗ។ ចម្លើយសុខភាព/ច្បាប់ជាព័ត៌មានទូទៅ មិនមែនដំបូន្មានវេជ្ជសាស្ត្រ ឬច្បាប់ទេ។
- fuzzy search ស្កែនគ្រប់ alias (~៦២,០០០) ក្នុងសំណួរនីមួយៗ។ ល្បឿនមិនទាន់ត្រូវបានវាស់ក្នុងឯកសារនេះទេ។ បើយឺត ត្រូវកំណត់ fuzzy តាមប្រវែង ឬ index។
- ទិន្នន័យនេះជា Q&A ចម្លើយតាម trigger មិនមែន corpus អត្ថបទសម្រាប់ train ទេ ហើយ **មិនរាប់** ក្នុងគោលដៅពាក្យ (`CORPUS_STRATEGY.md`, `HANDOFF.md`)។
- ខ្លឹមសារជា **synthetic (បង្កើតដោយ AI)** ដូច្នេះមិនត្រូវរាយការណ៍ថាជាអត្ថបទដែលមនុស្សសរសេរទេ (តាមច្បាប់ក្នុង `CORPUS_STRATEGY.md`)។
